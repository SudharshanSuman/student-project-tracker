# IIC Management Platform

**Student Project Tracker** — a management platform for a university **Innovation Incubation Cell (IIC)**: student startup/project portfolios, agile task boards, academic stage-gate approvals, QR-based event attendance (web + native Android scanner), Discord voice/engagement telemetry, GitHub repo sync, hackathon & competition tracking, funding/grant ledgers, automated PDF reporting, and a role-based executive dashboard.

Everything is backed by a real PostgreSQL database with real authentication and authorization — there is no mock data in the core product; seed data used for local development is explicitly labelled `[Demo]`.

Full original requirements: [SPEC.md](SPEC.md). Architecture, auth model and trade-offs: [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).

## What it does

Four roles — **Admin**, **Mentor**, **Project Lead**, **Project Member** — share one platform:

- **Project & team management** — portfolio directory, stages (`Ideation → PoC → MVP → Market Testing → Pre-Incubation Launch`), membership, repo links, document uploads, audit trail.
- **Kanban task board** — `TODO → IN_PROGRESS → REVIEW → DONE`, dependencies, drag-and-drop, role-gated transitions.
- **Stage-gate milestones** — students submit evidence, mentors/admins approve or request changes with a mandatory comment; stage advancement is a separate, explicit, auditable action. Task completion never auto-advances a stage or unlocks funding.
- **Attendance** — event sessions with signed, short-lived, single-use QR codes (web camera or the native Android scanner); duplicate check-ins are rejected at the database level; manual correction is audited.
- **Discord telemetry** — voice-channel join/leave tracking and aggregate message counts via a bot, with verified-vs-incomplete session distinction. No message content or DMs are ever read.
- **GitHub integration** — per-project repo linking, commit/PR activity summaries, signed webhook ingestion. Commit counts are shown as supporting context, never as a contribution score.
- **Competitions & funding** — hackathon/competition directory, verified-vs-claimed outcomes, multi-currency funding ledger with admin-reviewed change requests.
- **PDF reporting** — project, cohort, attendance-compliance, milestone, competition, funding and executive-summary reports, generated by a bounded headless-Chromium worker pool and downloaded securely.
- **Executive dashboard** — every metric computed live from the database, scoped to what the signed-in role is allowed to see.

## Tech stack

| Layer | Choice |
| --- | --- |
| Web | Next.js 15 (App Router), React 19, TypeScript, Tailwind CSS 3, hand-written shadcn-style Radix components, Recharts, React Hook Form + Zod, dnd-kit, Lucide icons |
| API | Node 20, Express 5, TypeScript (ESM), Zod validation, pino structured logging, `ws` WebSocket hints |
| Database | PostgreSQL 17 via Prisma 6 — UUID primary keys, explicit foreign keys, migrations |
| Shared | `packages/shared` — enums, Zod schemas shared by web + API, Kanban/stage-gate workflow rules, nav/role map |
| Background jobs | BullMQ + Redis when `REDIS_URL` is set, otherwise an in-memory job runner with the same retry/backoff semantics |
| PDF generation | Puppeteer with a bounded headless-Chromium browser pool, Postgres-backed job queue |
| Mobile | Capacitor Android shell around the same web app, native ML Kit barcode scanner for QR check-in |
| Tests | Vitest + Supertest (API, against a real Postgres test database), Playwright (browser E2E) |

## Prerequisites

- Node.js **20+** and npm
- No Docker and no local PostgreSQL install required — local dev uses a self-contained embedded PostgreSQL 17 binary (`embedded-postgres` package), with real data on disk under `.dev-db/`.
- Already have Postgres (system install, hosted, Docker)? You can skip the embedded DB and point `DATABASE_URL` at it instead.

## Run it locally

```bash
npm install                      # installs all workspaces + generates the Prisma client
cp .env.example .env              # then set QR_TOKEN_SECRET (openssl rand -hex 32)
ln -s ../../.env apps/api/.env && ln -s ../../.env apps/web/.env

npm run db:start                  # terminal 1 — embedded PostgreSQL 17 on :5433, data in .dev-db/
npm run db:migrate                # apply Prisma migrations
npm run db:seed                   # demo data only — clearly labelled [Demo]; refuses to run against production

npm run dev                       # terminal 2 — runs API (:4000) and web (:3000) together
```

Open **http://localhost:3000**.

Without SMTP configured, invitation and password-reset emails are written to the API log instead of sent, and the admin invitation dialog shows the link directly so you can copy it.

## Environment variables

Full reference with comments: [.env.example](.env.example).

**Required everywhere:** `DATABASE_URL`, `QR_TOKEN_SECRET` (≥ 32 random characters — `openssl rand -hex 32`).

**Required in production:** `INSTITUTION_EMAIL_DOMAINS` (an empty list rejects every sign-up in production, so it must be set), `WEB_ORIGIN`, `APP_URL`, SMTP settings (`SMTP_HOST`/`SMTP_PORT`/`SMTP_USER`/`SMTP_PASS`/`SMTP_FROM`).

**Optional, enable features when set:** `DISCORD_BOT_TOKEN` + `DISCORD_GUILD_ID` (Discord telemetry), `GITHUB_TOKEN` + `GITHUB_WEBHOOK_SECRET` (GitHub sync), `REDIS_URL` (BullMQ background queues — falls back to an in-memory runner), `PUPPETEER_EXECUTABLE_PATH` / `PUPPETEER_NO_SANDBOX` / `REPORT_CONCURRENCY` / `REPORT_MAX_ATTEMPTS` / `REPORT_RETENTION_DAYS` / `REPORT_WORKER` (PDF reports).

Secrets are never sent to the browser. UI screens report integration *presence/health*, never raw values.

## Database

PostgreSQL 17 via Prisma 6. Entities include `User`, `Project`, `ProjectMembership`, `Cohort`, `Task`, `TaskDependency`, `Milestone`, `MilestoneSubmission`/`MilestoneReview`, `Event`, `AttendanceSession`/`AttendanceRecord`, `DiscordIntegration`/`DiscordVoiceSession`/`DiscordActivityDaily`, `GitHubIntegration`/`RepositoryActivityDaily`, `Competition`/`CompetitionRegistration`, `FundingAward`, `Document`, `Notification`, `AuditLog`, `GeneratedReport`. UUID primary keys, explicit foreign keys with deletion behaviour, indexes for dashboard/filter queries, duplicate-prevention constraints (e.g. one attendance record per session per user), decimal + explicit currency columns for money. Details and ER notes: [docs/DATABASE.md](docs/DATABASE.md).

## Integrations (Discord, GitHub, email)

Full setup guides (bot permissions, gateway intents, token scopes, webhook configuration) are in [docs/INTEGRATIONS.md](docs/INTEGRATIONS.md). Short version:

- **Discord** — bot needs `GUILD_VOICE_STATES` + `GUILD_MESSAGES` intents (message *content* is never requested or read). Tracks voice presence (verified vs. incomplete sessions) and daily message counts per monitored channel only.
- **GitHub** — a fine-grained, read-only Personal Access Token plus an HMAC-SHA256-signed webhook (`/api/integrations/github/webhook`). Tokens entered through the UI are encrypted at rest (AES-256-GCM).
- **Email** — any SMTP server; without one, outgoing emails are written to the API log instead of failing silently.

All three are optional — the app runs fully without any of them configured; the admin "Integration settings" screen shows exactly what's missing.

## PDF reports

Project, cohort, attendance-compliance, milestone, competition, funding and executive-summary reports render through Puppeteer against a bounded headless-Chromium pool, backed by a Postgres job queue (so no Redis dependency for this feature specifically). Jobs retry on failure, are logged, and generated PDFs expire after `REPORT_RETENTION_DAYS` (default 30). Details: [docs/REPORTS.md](docs/REPORTS.md).

## Android app

`apps/mobile` is a Capacitor shell that loads the same Next.js web app inside a native Android wrapper and adds one native feature: scanning the attendance QR code with the phone's camera via ML Kit. No data is stored on the phone — every page, login and byte of data comes from the normal web/API server.

Easiest path — grab a prebuilt APK from CI (no Android tooling needed): on GitHub, **Actions → Android APK → Run workflow**, then download `iic-platform-debug-apk` from the run's artifacts.

To build it yourself (needs Node 20+, JDK 21, Android SDK):

```bash
npm install
CAP_SERVER_URL=http://<your-dev-machine-ip>:3000 npm run sync -w @iic/mobile
npm run open -w @iic/mobile        # opens Android Studio → Run ▶
# or headless:
cd apps/mobile/android && ./gradlew assembleDebug
```

Full details: [apps/mobile/README.md](apps/mobile/README.md).

## Docker

`docker compose up --build` starts Postgres, Redis, the API (runs `prisma migrate deploy` on boot) and the web app. **Note:** these Compose files were written without a Docker daemon available on the original build machine, so they have not been run end-to-end yet — treat them as a documented starting point, not a verified path.

```bash

npm run test:e2e -w @iic/web     # Playwright: full browser journeys against the dev servers + seeded DB
```

## Security model (short version)

- Invite-only accounts; role comes from the invitation, never from the request body.
- Server-side session rows (hashed tokens), `httpOnly` + `SameSite` cookies, scrypt password hashing, account lockout after 5 failed logins, rate-limited auth routes.
- All authorization is enforced server-side (`apps/api/src/lib/access.ts`); records outside what you can see return `404`, so existence never leaks.
- CSRF via `SameSite` cookies + Origin allowlist; secure upload handling (type allowlist, content-signature check, random storage names, 10 MB cap); full audit logging for sensitive admin/document actions.

Full write-up: [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md#authentication).

## Known limitations

- Docker Compose files are unverified end-to-end (no Docker available on the original dev machine).
- PDF report jobs use a Postgres-backed queue rather than BullMQ, by design (no Redis dependency for that feature).
- Attendance eligibility in reports uses current project memberships; membership history isn't versioned yet.
- `npm audit` has some remaining findings, all requiring major framework upgrades (Next 16 / Prisma 7 / Tailwind 4 / eslint-config-next) — deliberately deferred while feature branches build on the current stack.
